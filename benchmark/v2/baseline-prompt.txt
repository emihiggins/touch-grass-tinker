INTERPRETATION RULES
- "only blue" or "nothing above blue" sets hard_max_difficulty="blue" even if UI says red/black. It does NOT imply preferred_difficulties=["blue"] unless a soft preference is also expressed.
- "mostly/prefer blue, reds allowed" sets preferred_difficulties=["blue"], not ["blue","red"]. Hard maximum stays the UI maximum unless explicitly overridden. A soft preference cannot fill a missing hard maximum.
- "intermediate" alone does not establish an Austrian grade or a preference. Preserve the UI maximum, or clarify hard_max_difficulty if absent.
- Contradictory "only blue AND include black" sets hard_max_difficulty=null, clarification_fields includes hard_max_difficulty; no soft preference is implied.
- "avoid" is a soft preference stored in avoided_lift_types, never a hard exclusion. "no", "without", "exclude" and "skip" are hard exclusions. Do not add an automatic first-lift exception. Negated avoidance adds neither list. If both soft and hard restrictions apply to the same type, keep the hard exclusion only.
- "no drag lifts" expands EXACTLY to ["platter","rope-tow","t-bar"]. "drag" is NEVER an output enum. "no surface lifts" additionally excludes "magic-carpet". Negated exclusions do not exclude that type.
- Use only catalog IDs and aliases. Unknown start/finish -> corresponding ID null and clarify it.
- Explicit duration overrides UI. A deadline caps, never extends, that duration. With start 10:00, selected 60 minutes and deadline noon, duration remains 60. Explicit 120 minutes with deadline 11:15 gives 75. A positive explicit duration is retained, even outside the old 15..240 range. Ten minutes stays 10; five hours stays 300. Only missing, contradictory or nonpositive durations require clarification. Do not invent or apply lift closing times: the planner checks the supplied operational scenario.
- Map current/shortest live queues -> live_queue_times; freshly groomed today -> live_grooming; off-piste -> off_piste; quiet/uncrowded -> crowding. Do not infer additional unsupported codes. Keep resolved UI fields when returning unsupported.
- A missing start time requires clarification, not an invented timestamp. Generic "whenever" does not resolve it.
