## Directed graph investigation

**Follow-up:** the [independent source-loop audit](loop-verification.md) found large junction gaps and overlapping difficulty tags. The cycles below are graph-structural results only; do not adopt this derivative topology without source-backed repair.

[Machine-readable evidence](evidence/flachau-directed-audit.json), generated by [audit script](scripts/audit_graph.py), extends the initial weak-connectivity audit. Reproduce using the exact pinned terrain URL and hash in [data sources](data-sources.md): download that file once, then run `python3 research/scripts/audit_graph.py /path/to/terrain.json`. No third-party code executed or packages installed.

Method: directed pistes follow from/to IDs; lift edges follow station order; candidate walking links are excluded. Find mutually reachable components and, for each lift, a piste-only path from its last station to its first. These checks ignore closures, time, erroneous source topology and real terrain.

Findings:

- Full graph: largest strongly connected components contain 66 and 57 nodes; 42 lift/piste return candidates.
- Blue-only pistes: largest strongly connected component has 35 nodes; 23 lift/piste return candidates across the whole dataset.
- The 35-node component contains Hirschkogelbahn, Buchaubahn, Straßalmbahn, Alpendorf Gondelbahn, Gernkogelbahn and Obergassalmbahn. This is the **Alpendorf sector**, not Flachau village proper. Prefer it for a bounded first audit.
- One piste rises more than 5 m from first to last coordinate: `trail:flachau:osd-7e329d2e1472-1`, Übungshang Edelweiss, source ref 45, 1176.8 m to 1188 m. Could be a connector, elevation error or direction problem; flag rather than auto-reverse.
- No missing referenced nodes under this construction. No terrain correctness, legal access, current operation or exact route-time claim follows from this result.

Next audit must verify source lift types (e.g. Buchaubahn is encoded as gondola), geometry-to-node snapping, piste difficulty and directed return paths. Require at least three verified lift/descent loops and two distinct meaningful route choices before accepting the sector. This gate remains open.

## Reuse choices

- **NetworkX:** official shortest-path documentation supports directed weighted graphs and Dijkstra. Use graph primitives, not a custom low-level graph library. Missing weights silently default to 1 in its API, so our importer must reject missing durations. https://networkx.org/documentation/stable/reference/algorithms/shortest_paths.html
- **MapLibre GL JS:** official README identifies open-source web mapping and BSD-3-Clause licensing. Use a local GeoJSON layer over a neutral background initially, avoiding a paid basemap or prohibited OpenSkiMap hosted tiles. https://github.com/maplibre/maplibre-gl-js
- **Tinker Cookbook:** official chat SFT recipe supports custom JSONL through `FromConversationFileBuilder`; use its rendering/training abstractions. Reviewed upstream revision `1c03a20fdda98156ccbec15728c0e2764b5a0bc3`. https://github.com/thinking-machines-lab/tinker-cookbook/tree/main/tinker_cookbook/recipes/chat_sl
- Do not copy SlopePlan application functionality as the contest's original contribution. Credit reusable data; our new work is the constraint interpretation benchmark, model customization and verified planner integration.

- Quickstart supports `create_lora_training_client`, base `create_sampling_client`, and checkpoint sampling. The separately named serverless inference beta currently lists only Inkling variants; do not assume a Qwen OpenAI-compatible production endpoint. Use SDK sampling behind our own adapter, subject to a smoke test.
- Account access, available models, credits, request limits, checkpoint retrieval and actual latency remain unverified. No credentials inspected, paid jobs launched or model downloads performed.

Budget method: estimate uncached input tokens × input rate + output tokens × sample rate + charged training tokens × train rate, each divided by 1e6; include repeated evaluations, retries and checkpoint storage (currently documented as $0.10/GB-month). For scale only, 1.44M charged Qwen3-8B training tokens would be $0.6336 at the observed training rate, excluding all other charges. Tokenization/masking, actual billable usage, promotions and billing prerequisites must be checked before execution. No spending authorized by this estimate.
